# 系統架構與資料結構選擇說明文件

本文件詳細說明系統中所採用的 6 個核心功能及其對應之資料結構與演算法評估。

---

## 1. 核心功能解析

### 功能 1: 正式報名與全域資料儲存
* **檔案與方法**：`EventRegistrationSystem.java` -> `register()`
* **使用之資料結構/演算法**：`ArrayList`
* **選擇原因**：需要動態擴增容量，且後續需要透過索引進行排序（Merge Sort）與二元搜尋。
* **未採用其他方法之原因**：未採用固定長度 Array 是因為報名人數動態變化；未採用 LinkedList 是因為不支援 O(1) 隨機存取，不利於排序與 Binary Search。

### 功能 2: 活動候補順序管理
* **檔案與方法**：`EventRegistrationSystem.java` -> `waitingQueue`
* **使用之資料結構/演算法**：`Queue` (`LinkedList` 實作)
* **選擇原因**：候補機制遵循「先來後到 (FIFO)」原則，`Queue` 提供直覺且高效的 `offer()` 與 `poll()` 操作。
* **未採用其他方法之原因**：未採用 `Stack` 是因為會造成 LIFO（後到者先遞補）的不公平現象。

### 功能 3: 取消報名與復原 (Undo)
* **檔案與方法**：`EventRegistrationSystem.java` -> `cancelStack`, `undoCancel()`
* **使用之資料結構/演算法**：`Stack`
* **選擇原因**：復原操作遵循「後進先出 (LIFO)」原則，最新的取消紀錄應最先被復原。
* **未採用其他方法之原因**：未採用 `Queue` 是因為 Queue 會先復原最早取消的紀錄，不符 Undo 邏輯。

### 功能 4: 報名資料依編號排序
* **檔案與方法**：`RegistrationAlgorithms.java` -> `mergeSortById()`
* **使用之資料結構/演算法**：`Merge Sort`
* **選擇原因**：提供穩定的 $O(N \log N)$ 時間複雜度，且屬於穩定排序 (Stable Sort)，適合多鍵值排序需求。
* **未採用其他方法之原因**：未採用 `Quick Sort` 是因為最壞情況會退化至 $O(N^2)$ 且非穩定排序。

### 功能 5: 依編號精確查詢
* **檔案與方法**：`RegistrationAlgorithms.java` -> `binarySearchById()`
* **使用之資料結構/演算法**：`Binary Search`
* **選擇原因**：在資料已排序前提下，查詢時間複雜度僅需 $O(\log N)$，大幅優於線性搜尋。
* **未採用其他方法之原因**：未採用 `Sequential Search` 是因為對大規模資料搜尋效率較低 ($O(N)$)。

### 功能 6: 依姓名非唯一值查詢
* **檔案與方法**：`RegistrationAlgorithms.java` -> `sequentialSearchByName()`
* **使用之資料結構/演算法**：`Sequential Search`
* **選擇原因**：姓名非唯一鍵值且未排序，線性搜尋能完整走訪陣列並收集所有符合條件的資料。
* **未採用其他方法之原因**：未採用 `Binary Search` 是因為資料未依姓名排序。

## 2. 資料結構與演算法比較表

| 資料結構 / 演算法 | 時間複雜度 (平均/最壞) | 空間複雜度 | 適用場景 | 主要優缺點 |
| :--- | :--- | :--- | :--- | :--- |
| **ArrayList** | 隨機存取 $O(1)$，插入/刪除 $O(N)$ | $O(N)$ | 需要頻繁查詢與排序的清單 | 支援隨機存取；中間插入刪除成本高。 |
| **Queue** | 入隊/出隊 $O(1)$ | $O(N)$ | 排隊、候補、FIFO 任務排程 | 保證公平性；無法隨機存取中間元素。 |
| **Stack** | 推入/彈出 $O(1)$ | $O(N)$ | 復原 (Undo)、LIFO 歷史紀錄 | 實作簡單；只能存取頂端元素。 |
| **Sequential Search** | $O(N)$ | $O(1)$ | 未排序資料或非唯一鍵值搜尋 | 不需預先排序；資料量大時速度較慢。 |
| **Binary Search** | $O(\log N)$ | $O(1)$ | 已排序資料之快速查詢 | 搜尋極快；必須預先排序資料。 |
| **Merge Sort** | $O(N \log N)$ | $O(N)$ | 追求穩定度與大規模排序 | 效能穩定且為穩定排序；需要額外空間。 |
